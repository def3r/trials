LLVM IR structural analysis · test/kcolor.cpp

The m-coloring backtracking search doesn't loop over candidates — it recurses through them.

That's the one structural fact that matters. MaxCut and TSP's matchers both look for an outer Loop that enumerates an exponential candidate space and tracks a best value across iterations. solve() has no such loop — the candidate space (colors 0, 1, 2, … at each recursion depth) is walked by a small, bounded, per-call loop plus a self-recursive call. The identifying shape is still simple; it's just a different primitive.

Identifiable

solve() compiles to a clean, four-block loop with a single self-recursive call site, a guard call (isSafe), and a textbook assign → recurse → backtrack idiom on the same memory location. Everything a matcher needs is visible after mem2reg + simplifycfg + instcombine alone. loop-simplify and lcssa verifiably change nothing on this IR — both loops already have a single preheader and a single latch, and no loop-local value is read after the loop exits. indvars is actively unhelpful here: it widens the counters to i64 and, in solve(), inserts an extra block just to clamp a trip count that was never going to be negative.

01

What had to change to compile it

The version you pasted declared int color[N] and bool graph[101][101] as raw C arrays — the first is a VLA with a brace initializer, which neither C nor C++ permits (error: variable-sized object may not be initialized). I rewrote both as vector<int> and vector<vector<int>>, matching how maxcut.cpp and tsp.cpp already take their graph/cost-matrix input — so the same operator[]-call recognition the existing matchers use applies here too, instead of needing a second indexing pattern for raw GetElementPtrInst chains. The algorithm itself is untouched.

02

The shape, after canonicalization

This is solve()'s entire body post sroa,mem2reg,simplifycfg,instcombine — no loop-simplify, no lcssa, no indvars. Five basic blocks, one phi, one recursive call.

solve() · stage A (sroa,mem2reg,simplifycfg,instcombine)
entry:
  %cmp = icmp eq i32 %node, %N                    ; base case: node == N
  br i1 %cmp, label %return, label %for.cond

for.cond:                                       ; preds = %entry, %for.inc
  %i.0 = phi i32 [ %inc, %for.inc ], [ 1, %entry ]  ; candidate color, 1..m
  %cmp1.not = icmp sgt i32 %i.0, %m
  br i1 %cmp1.not, label %return, label %for.body

for.body:                                       ; preds = %for.cond
  %call = call i1 @isSafe(node, color, graph, N, i.0)   ; guard call
  br i1 %call, label %if.then2, label %for.inc

if.then2:                                       ; preds = %for.body
  %call3 = call ptr @vector::operator[](%color, %node)
  store i32 %i.0, ptr %call3                       ; color[node] = i   (assign)
  %add = add nsw i32 %node, 1
  %call4 = call i1 @solve(%add, %color, %m, %N, %graph)  ; SELF-RECURSIVE CALL
  br i1 %call4, label %return, label %if.end6

if.end6:                                        ; preds = %if.then2
  %call8 = call ptr @vector::operator[](%color, %node)
  store i32 0, ptr %call8                          ; color[node] = 0   (backtrack)
  br label %for.inc

for.inc:                                        ; preds = %for.body, %if.end6
  %inc = add nuw nsw i32 %i.0, 1
  br label %for.cond

return:                                         ; preds = %for.cond, %if.then2, %entry
  %retval.0 = phi i1 [ true, %if.then2 ], [ true, %entry ], [ false, %for.cond ]
  ret i1 %retval.0
base case

entry: an equality compare between the recursion-depth parameter (node) and the problem-size parameter (N). True path returns success directly — no recursive call, no loop.

candidate loop

for.cond/for.body/for.inc: a plain bounded counting loop, 1..m. Not a search-space enumeration loop like MaxCut's subset walk — m is the color count, not the problem size.

guard call

for.body calls a separate, non-recursive helper (isSafe) and branches on its boolean result. Structurally the same "recognized helper call gates a branch" shape tsp_pass.cpp already uses for next_permutation.

self-call

if.then2: solve calls solve. This is the one primitive MaxCut/TSP's matchers never needed — CB->getCalledFunction() == &F, nothing more exotic.

assign/backtrack

Same memory location (color[node]), written before the recursive call and rewritten after a failed one. The classic backtracking idiom, and a clean, checkable invariant: same GEP/index, two stores, one recursive call between them.

terminal phi

return merges exactly three incoming values: success-from-base-case, success-from-recursion, failure-from-exhausted-loop. A 3-way phi is itself part of the signature — a plain enumeration loop (MaxCut/TSP style) wouldn't produce this shape.

03

What passes/analyses actually earn their keep

Evidence-based, not assumed — each row below is checked against an actual diff of the pipeline stages (exhibits in §04).

Pass / analysisVerdictWhy
sroa + mem2reg essential Same as MaxCut/TSP — promotes node/i/scalar temporaries off the stack. Without it every block is buried in alloca/store noise (see the raw exhibits below).
simplifycfg + instcombine essential Collapses the if (isSafe) { assign; recurse; } source shape into the clean 5-block CFG above — without it, the guard/assign/backtrack blocks stay fragmented across extra empty blocks.
LoopInfo still needed Not for an outer search loop (there isn't one) — but the color-trying loop inside solve and the neighbor-check loop inside isSafe are both real Loops, and the same phi/preheader/latch primitives tsp_pass.cpp already has apply directly.
loop-simplify no-op here Diffed stage A against stage A+loop-simplify+lcssa+indvars: both loops already have exactly one preheader and one latch post-simplifycfg. Nothing changes except what indvars separately does (next row).
lcssa no-op here grep -n lcssa on the fully-piped IR: zero matches. Neither loop's induction value is used after the loop exits — both functions return straight out of loop-adjacent blocks, so there's nothing for LCSSA to reconcile.
indvars actively unhelpful Widens i32 counters to i64 (extra casts to strip, same as stripIntCasts already handles) and rewrites icmp sgt i.0, m to an eq-against-trip-count form gated by a new llvm.smax.i32 clamp — adding a whole extra block in solve() that isn't there without it.
self-recursion check new, but small Not an existing LLVM pass — just CB->getCalledFunction() == &F on a CallBase inside F itself. No call-graph SCC analysis needed for a single self-call.

05

What's actually new to build

Everything in tsp_pass.cpp's toolbox — phi/latch/preheader matching on Loop, operator[] call recognition, stripIntCasts, side-effect gating on non-recognized calls — carries over directly to the two small loops here. The one genuinely new primitive is detecting the self-recursive edge and its paired assign/backtrack stores:

match target

A CallBase in function F whose getCalledFunction() == &F.

recursion arg

One argument to the self-call must be a simple recurrence of a parameter (here, node + 1) — the recursion-depth counter.

base case

An entry-block (or entry-dominating) compare of that same parameter against another parameter or loop-invariant bound, short-circuiting to a success return.

store pairing

A store to some index[depth-param] location strictly before the self-call, and a second store to the same GEP/index strictly after it on the failure edge — the backtrack invariant.

candidate loop

The self-call and its guarding branch must live inside a Loop whose trip count is a separate parameter (m) from the recursion bound (N) — that's what distinguishes "try each candidate at this depth" from an unrelated loop.
